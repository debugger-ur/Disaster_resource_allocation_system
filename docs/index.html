Simple, explainable workflow

How DRRAS works

Automation helps with sorting and suggestions. People make the final decisions.

1

Submit

A citizen selects the disaster type, places a pin, describes the need and requests resources.

2

Check

The server validates fields, compares the report with recent reports and calculates a transparent risk score.

3

Review

A coordinator sees duplicate matches and risk reasons. They approve, reject or ask for information.

4

Allocate

Nearby centres are ranked by stock, road distance, travel time and availability. Stock is deducted when confirmed.

Duplicate detection

The system compares disaster category, location within 50 km, description similarity and submission time inside a configurable window. The admin sees the matching ID and the exact points contributed by each factor.

Never automatic: a duplicate warning only asks a human to compare the reports.

Automatic approval

Administrators can turn on safe auto-approval. It requires low risk, complete contact details, a minimum description length, an allowed severity and no duplicate warning. Any failed condition sends the report to manual review.

Default: auto-approval is off until an administrator enables it.

Data honesty

All help centres in this repository are labelled sample data for a college project. Map tiles come from OpenStreetMap. Road distances and ETAs come from OSRM; when it is unavailable, the interface shows a clearly labelled estimate and does not draw a route line. Email and SMS notifications are not implemented.
