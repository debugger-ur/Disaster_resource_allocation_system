Automated checks

Transparent verification

  • Duplicate detection
    Compares location, category, wording, timing, contact and resource type with recent reports. You are warned, never rejected.
  • Risk scoring
    Checks missing or invalid contact details, repeated submissions, inconsistent locations and reused files.
  • Human review
    Medium and high-risk reports wait for a coordinator. High-risk requests are never silently discarded.
  • Audit trail
    Every approval, rejection, merge and dispatch is recorded with the reviewer and reason.

What happens next

  1. Submitted — you receive an ID immediately.
  2. Verification — duplicates and risk signals are checked.
  3. Approval — a coordinator (or a rule you can audit) approves.
  4. Resources assigned — nearest suitable centre is selected.
  5. In progress → resolved — delivery is tracked.

Workflow

How DRRAS handles a report

A verification pipeline designed to catch errors without ever discarding a genuine emergency.

Step 1

Validate & accept

Server-side validation checks required fields, coordinate ranges, resource categories and file types. A request ID is issued immediately.

Step 2

Detect duplicates

The report is compared with recent reports on location proximity, disaster category, description similarity, timing, contact details and resource overlap. Matching IDs and locations are shown to a coordinator.

Step 3

Score risk

Each signal adds transparent points: missing description, invalid phone, repeated submissions, location mismatch, reused evidence. Low/medium/high thresholds are configurable.

Request statuses

Exactly where a report can be at any time.

  • Submitted Received and queued.
  • Under verification A person is checking the details.
  • Possible duplicate Another report may describe the same incident.
  • Awaiting approval In the coordinator's approval queue.
  • Approved Eligible for resource allocation.
  • Rejected Closed by a person, with a recorded reason.
  • Resources assigned Stock committed from a centre.
  • In progress Dispatch under way.
  • Resolved Response complete.

Protections

What the system will not do

  • Reject a report automatically because a risk score is high.
  • Discard a high-risk or uncertain case silently.
  • Approve anything automatically unless an administrator has enabled explicit rules.
  • Show contact details or evidence publicly.

Map data

Distances are honest

Road distance and travel time come from the OSRM routing engine through the server. Where routing is unavailable, the interface labels the figure as an estimate and does not draw a route line.

Help-centre records in this deployment are realistic sample data. Verify them before operational use.
